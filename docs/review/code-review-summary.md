## Top 10 Findings

### 1. XSS in HTML Reports (Critical — Security)

**Affected**: All HTML reports generated by all check modules
**Evidence**: shared_Functions.psm1 JavaScript renders tenant-derived data (display names, descriptions, group membership rules) into HTML tables. The data path is: Graph API → JSON → PowerShell object → JSON embedded in HTML `<script>` tag → JavaScript parses and renders into DOM.
**Risk**: An attacker who controls any display name in the assessed tenant could inject JavaScript that executes when a reviewer opens the HTML report.
**Status**: Acknowledged in README as a known limitation.
**Recommendation**: HTML-encode all tenant-derived data before rendering.

### 2. Managed Identities AppRoles Always Zero (Medium — Bug)

**Affected**: `check_ManagedIdentities.psm1` line 697
**Evidence**: `$AppRoles = ($MatchingAppRoles | Measure-Object).count` references `$MatchingAppRoles` which is never defined or populated.
**Impact**: The AppRoles column in the Managed Identities report is always 0. AppRole details are always null.
**Recommendation**: Implement AppRole collection for managed identities, similar to Enterprise Apps.

### 3. CSV Injection in Exported Data (Medium — Security)

**Affected**: All CSV exports (client-side JavaScript)
**Evidence**: CSV export extracts visible cell content without sanitization. Values starting with `=`, `+`, `-`, `@` could trigger formula execution in spreadsheet applications.
**Recommendation**: Prefix values with a tab or single quote character in CSV output.

### 4. App Registration Credential Expired Flag Not Reset (Medium — Bug)

**Affected**: `check_AppRegistrations.psm1` lines 298-305, 328-335
**Evidence**: The `$Expired` variable is not reset at the start of each credential iteration. A credential with no `EndDateTime` inherits the Expired status from the previous credential.
**Recommendation**: Initialize `$Expired = $false` at the start of each iteration.

### 5. Risk Formula Inconsistency (Low — Maintainability)

**Affected**: All scoring modules
**Evidence**:
- Users: `[math]::Round(Impact × Likelihood)`
- Groups: `[math]::Ceiling(Impact × Likelihood)`
- Enterprise Apps: `Impact × Likelihood` (raw, then Round in post-processing)
- Managed Identities: `Impact × Likelihood` (raw)
- App Registrations: `[math]::Round(Impact × Likelihood)`
**Impact**: Makes cross-module risk comparisons unreliable (though the README explicitly warns against this).
**Recommendation**: Standardize the rounding approach across all modules.

### 6. App Registration O(N×M) Performance (Medium — Performance)

**Affected**: `check_AppRegistrations.psm1` line 606
**Evidence**: For each App Registration, the code iterates the entire Enterprise Apps hashtable to find the matching SP by AppId. With 1000 app registrations and 5000 enterprise apps, this is 5 million iterations.
**Recommendation**: Build a hashtable lookup by AppId before the main loop.

### 7. Role Assignment Type Never Matches (Medium — Bug)

**Affected**: `check_Roles.psm1` line 91
**Evidence**: `$normalizedType -eq "AppRegistration"` but `$normalizedType` is always lowercased (line 31), so the comparison against PascalCase "AppRegistration" never matches. App registrations passed with this type fall through to the unknown fallback.
**Recommendation**: Use `"appregistration"` (lowercase) for the comparison.

### 8. BroCiToken Visible in Command Line (Medium — Security)

**Affected**: `run_EntraFalcon.ps1` parameter definition
**Evidence**: The `-BroCiToken` parameter accepts a refresh token as a plain string argument, visible in process lists and shell history.
**Recommendation**: Support prompting for the token interactively, or accept it via stdin/environment variable.

### 9. Null JavaScript Interpolation Risk (Medium — Bug)

**Affected**: `export_Summary.psm1` lines 339-488
**Evidence**: PowerShell variables from `$GlobalAuditSummary` are interpolated into JavaScript code. If any value is `$null`, the resulting JavaScript will be syntactically invalid (e.g., `internal: ,`).
**Recommendation**: Provide default values (0) for all summary fields before interpolation.

### 10. Import-Module Backslash Paths (Low — Portability)

**Affected**: `run_EntraFalcon.ps1` lines 127-141
**Evidence**: Module paths use literal backslash: `Join-Path $ScriptRoot 'modules\EntraTokenAid.psm1'`. While `Join-Path` handles the first argument cross-platform, the backslash within the string literal `'modules\...'` is passed as-is. On Linux, PowerShell may resolve this, but it's not guaranteed in all scenarios.
**Recommendation**: Use `Join-Path (Join-Path $ScriptRoot 'modules') 'EntraTokenAid.psm1'` or forward slash.

## Positive Observations

1. **Clean architecture**: Well-organized module structure with clear separation of concerns
2. **Robust retry logic**: All API clients implement exponential backoff with retry
3. **Pagination handling**: Automatic pagination for both single and batch Graph requests
4. **PKCE by default**: Auth code flow uses PKCE challenge, improving security
5. **State validation**: OAuth state parameter is validated to prevent CSRF
6. **Comprehensive checks**: 63 security findings cover a wide range of Entra ID misconfigurations
7. **Rich reporting**: Interactive HTML reports with filtering, sorting, and cross-navigation
8. **Token cleanup**: Global variables are removed on script completion
9. **Configurable verbosity**: Four log levels for debugging
10. **CAE support**: Continuous Access Evaluation requested by default for longer-lived tokens
